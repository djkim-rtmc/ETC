## 1. 무엇을 만드는가

보건소에 **구축형**으로 제공하는 예방접종·안심QR 서비스다.

- 기존 **유저웹**을 보건소용으로 커스터마이징한다.
- **병원 OCS와는 연동하지 않는다.** 접종 등록에 필요한 데이터는 우리 서비스(유저웹 + Vd-IMS + 안심예방접종)에서 모두 수집한다.
- 질병관리청 예방접종 자동등록은 **현행 IR24(SOAP 표준모듈)** 기준으로 연동한다.
- 주민번호 등 개인정보는 민간 회사가 상시 수집·보유하기 어려우므로, **보건소(공공기관)가 처리자가 되는 공공클라우드 테넌트**에 두고 운영한다.

### 구성 제품 (역할)

| 제품 | 역할 |
|------|------|
| 보건소 유저웹 | 보호자/피접종자 가입, 가족·QR, 접종 전 개인정보 임시 입력, 접종 이력·자가체크 |
| RTMC-TAB | 접종실 QR·바코드 스캔 |
| 안심예방접종 | 의료진 접종 확인·확정 UI |
| Vd-IMS | 기관·계정·통계·질병청 등록 오케스트레이션 |
| 질병청 Adapter | IR24 `VcnRegInfo` 조립·Register·결과 처리 (차세대 시 교체 지점) |

## 2. 핵심 원칙

1. **OCS 대체**: 기존 가이드의 OCS Local DB 역할을 구축형 DB가 수행한다.
2. **개인정보 주체**: 처리자 = 보건소 / 수탁자 = 회사(RTMC).
3. **민감정보 최소·단기**: RRN·주소는 접종 직전 입력 → 질병청 ACK 후 파기(또는 QR 만료 시 파기).
4. **IR24 필수값 완전 수집**: 피접종자·접종·의료진·기관 필드를 서비스 내에서 빠짐없이 채운다.
5. **의료진 필수값 = Vd-IMS 계정**: 접종자 성명·예진의사명은 계정 상세에서 등록·수정한다.

## 3. 전체 프로세스 (요약)

```
[보호자] 게시 QR → 유저웹 로그인/가입 → 대상자 선택
       → (접종 당일) RRN·주소 입력 → 접종용 QR(단기)
              ↓
[의료진] TAB으로 접종용 QR + 백신 바코드 스캔
       → 안심예방접종에서 확인(의료진 정보는 계정에서 자동)
       → Vd-IMS가 IR24로 질병청 등록
              ↓
       성공(ACK) → RRN·주소 파기 + 이력만 유지
       실패 → 재시도 큐 / 담당자 알림
              ↓
[보호자] 유저웹에서 접종 이력·자가체크·알림
```

## 4. 단계별 프로세스

### 4.1 온보딩 (보건소 구축)

| 순서 | 주체 | 내용 |
|------|------|------|
| 1 | 영업·기획 | 공공클라우드 옵션·계약(처리자/수탁) 확정 |
| 2 | 인프라 | 보건소 테넌트 개설(IaC), CSAP 등 요건 확인 |
| 3 | Vd-IMS | 기관코드·명, 요양기관코드, 질병청 연계 Usrid/Pwd 등록 |
| 4 | Vd-IMS | 의료진 계정 생성 — **접종자 성명·예진의사명 필수 입력** |
| 5 | 운영 | 게시용 QR(URL) 발급·부착, TAB 반입, 알림 채널 |
| 6 | 공통 | 개발업체명 등 시스템 상수·브랜드 커스텀 |

### 4.2 보호자·피접종자 (유저웹)

| 순서 | 내용 | 수집되는 IR24 성격 데이터 |
|------|------|---------------------------|
| 1 | 게시 QR 스캔 → 로그인/본인인증 | CI 등 식별(상시). RRN 아님 |
| 2 | 본인·자녀(가족) 등록 | 성명, 생년월일, 관계, 쌍둥이구분, 연락처, 동의 |
| 3 | 접종 방문 시 대상 선택 → RRN·주소 입력 | 주민번호, 주소, (필요 시) 보호자 주민번호 |
| 4 | 접종용 QR 발급 (예: 30초, 대상 ID 토큰) | QR에 PII 미포함 |
| 5 | 미사용·만료 시 임시 PII 자동 파기 | — |

### 4.3 접종 (현장)

| 순서 | 내용 | 수집·사용 데이터 |
|------|------|------------------|
| 1 | TAB에서 접종용 QR 스캔 | 대상 식별(토큰) |
| 2 | 백신 바코드/제조번호 스캔 | 로트·유효기간·백신코드 (조회) |
| 3 | 의료진 확인·방법·부위·용량·차수 등 | 접종정보 + **계정에서 가져온 접종자/예진의** |
| 4 | 확정 → 질병청 Register | VcnRegInfo 전체 조립 |
| 5 | 결과 처리 | 전송상태 저장, 성공 시 PII 파기 |

### 4.4 접종 후

| 순서 | 내용 |
|------|------|
| 1 | 유저웹 접종 이력 반영 |
| 2 | 이상반응 자가체크·알림 (기존 서비스 모델 커스텀) |
| 3 | (선택) 비식별 집계만 회사 중앙으로 배치 |

## 5. 데이터·권한 경계

```
┌─────────────────────────────────────────────┐
│ 보건소 공공클라우드 테넌트 (처리자: 보건소)   │
│  · 유저웹 DB · 가족/동의 · 접종 이력         │
│  · RRN·주소 임시저장 · 의료진 계정           │
│  · 질병청 전송 로그·파기 감사로그            │
└───────────────────┬─────────────────────────┘
                    │ 등록 API (IR24)
                    ▼
              질병관리청
                    │
┌───────────────────┴─────────────────────────┐
│ 회사 중앙 (수탁·운영)                         │
│  · 메타/버전 배포 · 알림 오케스트레이션        │
│  · 비식별·집계 (원본 RRN 미보유)              │
└─────────────────────────────────────────────┘
```

- 의료진 단말(안심예방접종)에는 **이름·생년월일 등 식별용 최소 정보**만 표시하고, RRN·주소는 표시하지 않는 것을 원칙으로 한다.
- 알림 CSP 등은 재위탁 범위를 계약서에 명시한다.

## 6. Vd-IMS 계정과 의료진 필수값

계정 관리 > 계정 상세에 IR24 의료진 필드를 **추가 입력**한다.

| 필드 | IR24 | 용도 |
|------|------|------|
| 접종자 성명 | injnam | 질병청 접종 등록 시 접종자 |
| 예진의사 성명 (또는 예진 여부 + 성명) | exmdtrnam | 질병청 예진의사 |

- 계정 저장 시 권한에 따라 필수 검증.
- 접종 화면에서는 로그인 계정 값을 기본 넣고, 예진 의사만 당일 선택이 가능하도록 할 수 있다.
- 상세 매핑은 `IR24_필수값_화면_테이블_매핑표_v0.1.md` §5 참고.

## 7. 질병청 연동 (현행)

| 항목 | 내용 |
|------|------|
| 방식 | SOAP Web Service (`VcnRegService.Register`) |
| 페이로드 | `VcnRegInfo` (인적 + 접종 + 기관 자격) |
| 사전검증 | IR24 §4 필수항목 검사 (로컬에서 선검증 권장) |
| 백신 | 제조번호 조회 → 로트/유효기간/약품코드 채움 |
| 결과 | pflag/vflag, errmsg 등 → 테넌트 접종 레코드 상태 갱신 |
| 차세대(참고) | 2027.3 WEB·JWT 표준모듈 — **Adapter만 교체**할 수 있게 설계 |

## 8. 기존 SaaS 유저웹과의 차이

| 구분 | 기존(민간 SaaS) | 보건소 구축형 |
|------|-----------------|---------------|
| 제공 형태 | 클라우드 SaaS | 보건소 테넌트(공공클라우드) |
| OCS | (해당 시) 병원 연동 검토 | **연동 없음** |
| 개인정보 처리자 | 계약에 따름(제약 큼) | **보건소** |
| RRN | 상시 수집 곤란 | 접종 직전 임시 → 파기 |
| 브랜딩 | RTMC | 보건소/공공 커스텀 |
| 의료진 정보 | — | **Vd-IMS 계정 필수** |

## 9. 역할 RACI (요약)

| 활동 | 보건소 | RTMC | 질병청 |
|------|--------|------|--------|
| 개인정보 처리 목적·동의 | A/R | C | I |
| 테넌트·계정·의료진 등록 | R | C/지원 | I |
| 접종 확정·현장 운영 | R | C | I |
| IR24 등록 기술 구현 | I | R | A(규격) |
| PII 파기·감사 | A/R | R(기능제공) | I |
| 알림 발송 운영 | C | R(수탁) | I |

A=Accountable, R=Responsible, C=Consulted, I=Informed

## 10. 리스크·주의

| 리스크 | 대응 |
|--------|------|
| 민간 회사의 RRN 상시 보유 | 공공클라우드 + 처리자=보건소 + 임시저장·파기 |
| OCS 없이 필수값 누락 | 매핑표 기준으로 화면 필수 검증 |
| 의료진명 미입력 | Vd-IMS 계정 저장 차단 |
| 질병청 등록 실패 | 재시도 큐, PII는 TTL 내만 유지, 실패 시 담당 알림 |
| 2027 차세대 전환 | Adapter 계층으로 결합도 분리 |
| 공공 클라우드 인증(CSAP 등) | 온보딩 전 CSP·인증 트랙 확인 |

## 11. 권장 추진 순서

1. 계약·처리자/수탁·공공클라우드 옵션 확정
