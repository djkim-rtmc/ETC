## 1. 전제

1. 서비스 이름: **비대면 상담**. (레거시 파일명은 `원격진료` / `원격상담`을 쓸 수 있다)
2. 접종자 식별은 **RTMC 유저 ID**. 별도 외부 가입 없음.
3. 예약·스케줄·확정·화상상담(상담실)·전사/SOAP·로컬 다운로드는 **전부 RTMC 내장**.
4. 화상은 **WebRTC** 가정. 외부 상담 웹·새 탭 연동 없음.
5. 상담기록 **본문은 서버 미보관**. 상담실에서 **로컬 다운로드만**. 플랫폼은 상태·일시·담당 의료진 등 **메타만** 보관.
6. 비대면 상담은 자가체크 결과를 참고하는 **선별·상담**이다. 진단·처방이 아니며, 응급은 119·가까운 의료기관.

## 3. 용어 · 상태

내부 코드는 A 목업의 9종을 유지한다. 화면 표기는 **비대면 상담** 톤(B·C)으로 맞춘다.

| 내부 코드 | 의료진 화면 | 유저웹 화면 | 의미 |
|---|---|---|---|
| 해당없음 | 해당없음 | 미신청 | 해당 회차에 상담 없음 (기본·새 회차 덮어쓰기) |
| 진료요청 | 상담요청 | 예약 대기 | Case B — 의료진이 요청 알림톡 발송, 접종자 **일정 미선택** |
| 예약대기 | 예약대기 | 예약대기 | Case A 접종자 신청 완료 **또는** Case B 일정 선택 완료 — 의료진 확정 대기 |
| 예약확정 | 예약확정 | 예약확정 | 의료진 확정. 접속 URL 알림톡 발송. **상담 시작 15분 전**부터 상담실 입장 가능 |
| 진료중 | 상담중 | 상담중 | 상담 시간대 세션 진행 (상담실 입장·화상 상담) |
| 진료완료 | 상담완료 | 상담완료 | 정상 종료 |
| 진료취소 | 접종자 취소 / 의료진 취소 | 직접취소 / 예약 취소 | `cancelBy`: 접종자(유저웹 취소) · 의료진(예약 취소 알림톡) |
| 진료불참 | 상담불참 | 불참 | 노쇼 |

### 3.1 Case별 확정 전

- **Case A**: 접종자 신청 완료 ~ 확정 전 = **예약대기**
- **Case B**: 요청 직후 ~ 스케줄 미선택 = **상담요청** / 스케줄 선택 후 ~ 확정 전 = **예약대기**

### 3.2 회차 (1~4차)

| 규칙 | 내용 |
|---|---|
| 의료진 목록 1행 | **접종자(접종 건) 단위** 1행 |
| 목록 「비대면 상담」열 | **최신 회차** 상태만. 새 회차 자가체크 시 **해당없음**으로 덮어씀 |
| 의료진 상세 탭 | **1~4차 칩**으로 회차별 이력 **유지** |
| 유저웹 허브 | 진행 중 / 지난 상담 **카드 목록**. 카드 1장 = 상담 1건 |
| 유저웹 상세 | 연결된 자가체크는 **해당 상담과 연계된 차수 1건만** |
| 상담 요청 | **최신 회차**이면서 상태가 **해당없음**일 때만 활성 |
| 가족 | 유저웹 허브는 **본인·가족** 카드를 함께 둘 수 있다 (B 목업) |

## 4. 프로세스

### 4.1 Case A — 접종자 직접 신청

진입: 홈 상태영역 CTA 또는 자가체크 결과 「비대면 상담 신청하기」  
조건: **7일 내 자가체크 완료** + 해당 회차 상태가 **해당없음**(진행 중 건 없음)

```
[유저웹] 신청하기
    ↓
[유저웹] 의료진 선택 → 일정(시간 슬롯) 선택 → 확인
    ↓
[유저웹] 신청 완료 **페이지** → 홈
    ↓  상태: 예약대기
[유저웹] 홈 상태바 · 허브 카드 (일정 · 의료진 · 안내 · 취소)
    ↓
[의료진 · 예약] 「예약 확정」→ 확정 메시지 발송
    ↓  상태: 예약확정
[RTMC] 접종자 알림톡 (상담실 접속 URL)
    ↓
[RTMC] 당일 1시간 전 리마인드 (동일 URL)
    ↓  상태: 상담중 (입장·세션 시작)
[상담실] 화상 + 전사/SOAP + 자가체크·AI → 종료
    ↓  상태: 상담완료
```

- Case A 신청 직후 **예약요청 알림톡은 보내지 않는다.**
- 신청 완료는 **전용 페이지** 후 홈으로 돌아간다.
- 홈 안내 예: 「일정이 확정되면 접속정보가 메시지로 발송됩니다.」

### 4.2 Case B — 의료진 요청

요청 액션은 **VD-IMS에서만** 한다.

```
[VD-IMS · 상세 또는 대시보드 「상담요청」] 메시지 발송
    ↓  상태: 상담요청
[RTMC] 접종자 알림톡 (일정 선택 URL → 유저웹)
    ↓
[유저웹] 해당 의료진 가용 스케줄만 선택 → 신청
    ↓  상태: 예약대기
[의료진 · 예약] 「예약 확정」
이후 Case A와 동일
```

### 4.3 접종자 취소

| 가능 | 불가 |
|---|---|
| 예약대기 · 예약확정 | **상담중** — 취소 없음, **상담실 입장만** |

```
[유저웹] 홈 상태바 / 허브 카드 / 상세 「취소」→ 확인 모달
    ↓  상태: 상담취소
```

취소 후에도 최근 자가체크가 있으면 **다시 신청**할 수 있다.

### 4.4 의료진 예약 취소

확정 전(예약대기) 건.

```
[예약 상세] 「예약 취소」
    ↓
[예약 취소 메시지] 초안 확인 → 발송
    ↓  상태: 상담취소 · 선택 일정 해제
```

톤: 정중히 사과 + 유저웹에서 일정 재선택·재신청 안내.

### 4.5 당일 · 상담실

```
[의료진] 오늘 일정 「상담중」 또는 예약 「상담실」 → 상담실 팝업
[접종자] 허브·상세 「상담실」 → 동의 → 기기 → 대기 → 상담 → 종료
```

**상담실 입장 시각**

| 구간 | 상태(표기) | 입장 |
|---|---|---|
| 상담 시작 **15분 전** ~ 시작 직전 | 예약확정 | **입장 가능** — 기기 확인·대기실. UI는 핑크(접종자 입장 완료) 또는 회색(접종자 미입장) |
| 상담 시작 ~ 슬롯 종료(30분) | 상담중 | **입장 가능** — 핑크 + 강조 효과 |
| 그 외 | 예약확정 | 입장 버튼 비활성 |

- 의료진·접종자 **동일 정책**: 예약 확정된 건은 **시작 15분 전**부터 상담실 URL·입장 버튼 활성.
- 상태 코드는 시작 시각에 **예약확정 → 상담중**으로 전환. 입장 가능 시각과 상태 전환은 별개다.

**상담실 (A 목업)**

| 영역 | 내용 |
|---|---|
| 좌 | 환자 요약 + 전사 / SOAP / 메모 |
| 중 | 화상 (WebRTC) · 음소거·카메라·화면공유·**종료** |
| 우 | 자가체크 결과 → AI 분석 · 팝업 높이 내 스크롤 |

헤더: **상담기록 다운로드**(로컬) · 닫기. 세션 종료는 화상 영역 **종료**.

## 5. 알림톡 (RTMC 직접 발송)

| 유형 | 시점 | 포함 |
|---|---|---|
| 예약요청 | Case B 요청 직후 | 유저웹 일정 선택 URL |
| 예약확정 | 의료진 확정 직후 | **상담실 접속 URL** |
| 당일 리마인드 | 시작 **1시간 전** | 동일 접속 URL |
| 예약 취소 | 의료진 예약 취소 발송 시 | 사과 + 재신청 안내 |

- 상담 완료 알림톡 **없음** (웹 종료 화면으로 처리)
- KOI 발송 요청 API **없음**. RTMC가 상태 전이에 맞춰 직접 발송한다.

### 6.1 의료진 (VD-IMS)

사이드 레일 순서는 A, 「비대면 상담」 본문은 C.

| 2 | 상세 | A | 접종 정보 · 탭(자가체크 / 만족도 / AI / 비대면 상담 1~4차) · 「상담 요청 메시지」 |

#### 6.1.1 비대면 상담 대시보드 (C)

상단 툴바

- **상담 일정 보기** → A의 스케줄 보기 모달 (내 일정 / 기관 전체)
- **비대면 상담 접속하기** → 현재 열린 상담실이 있으면 입장, 없으면 비활성 (A의 「상담실 입장」과 동일)

KPI 4종

| KPI | 의미 |
|---|---|
| 상담 필요 (Level 4) | 고위험 자가체크 · 상담 추천 |
| 상담 권고 (Level 3) | 주의 자가체크 · 상담 추천 |
| 오늘 상담 예정 | 예약확정 · 상담실 대기 |
| 오늘 상담 완료 | 당일 완료 건 |

현황 파이프라인 (클릭 시 해당 상태 목록)

`상담요청 → 예약대기 → 예약확정 → 상담중 → 상담완료`  
종료 분기: `상담불참` · `상담취소`

하단

| 블록 | 내용 |
|---|---|
| AI 분석 결과 | Level 1~4 인원·비중 |
| 상담 검토 필요 | Level 3/4 대상 + **상담요청** 버튼 (Case B) |
| 오늘 일정 | 시간순 테이블 · 상담중이면 상담실 |
| 처리 필요 | 일정 미선택(상담요청) · 확정 필요(예약대기) |

스케줄 등록은 A와 같이 대시보드에서 **스케줄 등록하기**로 연다. (C 상단 「상담 일정 보기」와 짝)

### 6.2 접종자 (유저웹) — B 구조 + A 신청·당일 흐름

| 화면 | 기준 | 내용 |
|---|---|---|
| 홈 | B | 안심QR · **상태 영역만 전환** (미신청 CTA / 진행 중 상태바→상세) |
| 햄버거 | B | 「AI 유사성 분석」 아래 **비대면 상담** · 언어 선택은 로그아웃 위 |
| 허브 | B | 진행 중 / 지난 상담 카드. 카드 탭 → 상세. **취소·상담실만 카드 안 버튼** |
| 상담 상세 | B | 상담 정보 + 연결된 자가체크 1건. 예약대기=취소, 상담중=상담실 하단 고정 |
| 자가체크 결과 | B 구성 + A 신청 | 체크 완료·해당없음이면 「비대면 상담 신청하기」 → **RTMC 의료진 선택** (외부 웹 아님) |

## 9. 개발 범위 초안

### 포함

- 유저웹: 신청·일정·허브·상세·취소·당일 상담실 입장
- VD-IMS: 자가체크 연동, 요청/확정/예약 취소/재요청, 대시보드, 예약, 상담실
