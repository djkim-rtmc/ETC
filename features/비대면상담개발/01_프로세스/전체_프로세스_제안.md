# RTMC × 코이헬스케어(KOI) 비대면 상담 연동 프로세스

| 항목 | 내용 |
|---|---|
| 문서 성격 | **코이헬스케어 공유·협의용** |
| 작성 | 리얼타임메디체크(RTMC) |
| 기준일 | 2026.09.01 |
| 버전 | v2.1 |

---

## 1. 전제

1. 비대면 상담 **서비스는 KOI가 RTMC에 제공**한다.
2. 접종자는 **KOI 별도 회원가입 없음**. 식별은 **RTMC 유저 ID**(`user_id`)로 한다.
3. 예약·스케줄·확정·화상상담(상담실)·상담기록 정리·로컬 다운로드는 **KOI 웹**에서 수행한다.
4. RTMC는 자가체크·AI·신청/요청 진입·**상태 표시**·**알림톡 발송**을 담당한다.
5. 의료진은 RTMC(VD-IMS)와 KOI를 **새 탭으로 동시 사용**한다. (**iframe 내재화 없음**)

---

## 2. 역할 분리


| 구분 | RTMC | KOI |
|---|---|---|
| 접종자 식별 | 유저 ID 발급·보관 | 별도 가입 없음. `user_id`로 식별 |
| 접종자 표시정보 | 원본 보관 | **마스킹 성명 · 연령대 · 성별**만 수신·표시 |
| 연락처 | 알림톡 발송용 보유 | **미전달** |
| 접종·AI·자가체크 원문 | VD-IMS에만 보관 | **미전달** |
| 알림톡 | **발송** | **발송 요청 API** 호출 + URL 제공 |
| 신청·요청 진입 | 유저웹 신청 / VD-IMS 의료진 요청 | — |
| 의료진·스케줄·확정·상담실 | — | **전부** |
| 의료진 계정 | VD-IMS 계정 | **SSO + JIT**로 KOI 계정·스케줄 소유자 생성 |
| 상담기록 | **서버 미보관** | 웹에서 정리 후 **로컬 다운로드**. KOI 서버 저장 여부는 RTMC와 **무관** |

## 3. 프로세스 (확정)

### 3.1 Case A — 접종자 직접 신청

```
[RTMC 유저웹] 「비대면 상담 신청」 → KOI 진입
    ↓
[KOI] 의료진 선택 → 해당 의료진 가용 스케줄 선택 → 신청 완료
    ↓  RTMC 상태: 예약대기
[KOI] 의료진 확인·확정
    ↓  RTMC 상태: 예약확정
[KOI → RTMC] 알림톡 발송 요청 (유형: 예약확정, URL: 비대면 상담 접속 URL)
    ↓
[RTMC] 접종자 알림톡 발송
    ↓
[KOI → RTMC] 알림톡 발송 요청 (유형: 당일리마인드, 상담 시작 1시간 전, 동일 접속 URL)
    ↓
[RTMC] 리마인드 알림톡 발송
    ↓
[KOI] 비대면 상담 진행 → [KOI → RTMC] 상태 콜백(상담완료)
```

- Case A 신청 직후 **예약요청 알림톡은 발송하지 않음** (화면 이동으로 충분).
- **예약대기**(Case A) = 접종자가 의료진·스케줄 선택까지 **신청을 완료한 상태**.

### 3.2 Case B — 의료진 요청

```
[RTMC VD-IMS] 의료진이 접종자에게 「비대면 상담 요청」
    ↓  staff_propose (user_id, case_id, staff_id)
[KOI] 건 생성 · booking_url 회신 · 담당 의료진 = 요청자
    ↓  RTMC 상태: 상담요청
[KOI → RTMC] 알림톡 발송 요청 (유형: 예약요청, URL: booking_url)
    ↓
[RTMC] 접종자 알림톡 발송
    ↓
[접종자] KOI에서 **해당 의료진** 가용 스케줄만 선택
    ↓  RTMC 상태: 예약대기
[KOI] 의료진 확인·확정
    ↓  RTMC 상태: 예약확정
이후 Case A와 동일
  (예약확정 알림톡 → 1시간 전 리마인드 → 상담 → 상태 콜백)
```

- 의료진의 **요청 액션은 RTMC(VD-IMS)에서만** 수행한다. KOI에 별도 「요청」 진입점은 두지 않는다.

### 3.3 취소

접종자(또는 협의된 주체) 취소 시 → 상태 **상담취소** 콜백.

## 4. 상태값 (RTMC 표시 기준)


| RTMC 표시 | 의미 |
|---|---|
| 해당없음 | 비대면 상담 없음 |
| 예약대기 | Case A — 접종자 **신청 완료** (확정 전) · Case B — 스케줄 선택 후 확정 대기 |
| 상담요청 | Case B — 의료진 요청·예약요청 알림톡 발송됨, 스케줄 미선택 |
| 예약확정 | 의료진 확정. **비대면 상담 접속 URL** 포함 알림톡 발송 |
| 상담중 | 상담 진행 |
| 상담완료 | 상담 종료 |
| 상담취소 | 취소 (접종자/의료진) |
| 상담불참 | 노쇼 |


- Case A: 신청 완료 ~ 확정 전 = **예약대기**
- Case B: 스케줄 선택 후 ~ 확정 전 = **예약대기**
- KOI 내부 코드 ↔ 위 상태 **1:1 매핑표**는 API 스펙에서 확정한다.

상태 변경 시 KOI → RTMC **상태 콜백**을 보낸다.  
상태 콜백과 알림톡 발송 요청 API는 **분리**한다.

## 5. URL 정의


| 필드명 (API) | 의미 | 사용처 |
|---|---|---|
| `booking_url` | 예약·일정 선택(변경) URL | Case B **예약요청** 알림톡 |
| `session_url` | **비대면 상담 접속 URL** (확정 후 상담실 입장용) | **예약확정**·**당일 리마인드** 알림톡 |


`session_url`은 기술 필드명일 뿐, 알림톡 본문에는 **비대면 상담 접속이 가능한 URL**을 넣는다.  
예약확정과 당일 리마인드에는 **동일한 비대면 상담 접속 URL**을 사용한다.

## 6. 알림톡 (확정)

| 항목 | 내용 |
|---|---|
| 발송 주체 | **RTMC** |
| 트리거 | KOI → RTMC **알림톡 발송 요청 API** (상태 콜백과 별도) |
| 링크 | KOI가 생성한 URL을 본문에 **그대로** 삽입 |


### 6.1 필수 알림 (3종)


| 유형 | 시점 | 포함 URL |
|---|---|---|
| 예약요청 | Case B — 의료진 요청 직후 | `booking_url` |
| 예약확정 | 의료진 확정 직후 | **비대면 상담 접속 URL** (`session_url`) |
| 당일 리마인드 | 상담 시작 **1시간 전** | **비대면 상담 접속 URL** (`session_url`) |


### 6.2 발송하지 않는 알림

- **상담 완료** 알림톡: **발송하지 않음** (웹 완료 안내로 처리)

### 6.3 발송 요청 API (초안)

```json
{
  "user_id": "RTMC 유저 ID",
  "case_id": "자가체크 건 ID",
  "alimtalk_type": "예약요청 | 예약확정 | 당일리마인드",
  "booking_url": "https://…",
  "session_url": "https://…",
  "scheduled_at": "2026-09-01T14:00:00+09:00",
  "staff_name": "의료진 표시명"
}
```

당일 리마인드: KOI가 예약 시각 기준 **1시간 전**에 발송 요청 API를 호출하는 것을 기본으로 한다.  
(인증·재시도·템플릿 변수는 개발 협의)

## 7. 의료진 접속 — SSO + JIT (확정)

의료진이 KOI에서 스케줄·예약을 운영하려면 **SSO만으로는 부족**하며, KOI에 의료진 마스터가 필요하다.


| 층 | 내용 |
|---|---|
| SSO | RTMC(VD-IMS) → **새 탭**으로 KOI 진입. 별도 KOI 비밀번호 로그인 없음 |
| JIT | 최초·갱신 시 RTMC가 의료진 프로필 제공 → KOI DB에 계정·스케줄 소유자 **upsert** |
| 인가 | `institution_id`, 역할, 사용상태 |


**JIT 최소 항목**: 의료진 ID, 성명, 소속기관 ID, 기관명, 역할, 사용상태

### 7.1 예약 관리 조회

- **기본**: 로그인한 의료진 **본인** 스케줄·담당 건
- **추가**: 동일 기관 **전체** 스케줄·건 조회 가능

### 7.2 진입 (협의)

```
https://{koi-host}/staff?
  staff_id={RTMC 의료진 ID}
  &institution_id={기관 ID}
  &token={SSO/OIDC}
```

## 8. 상담기록 (확정)


| 구분 | 방침 |
|---|---|
| RTMC 서버 | 상담기록 본문(SOAP·처치의견·상담요약 등) **미보관** |
| 다운로드 | 비대면 상담 웹에서 정리된 기록을 **의료진 PC 로컬 다운로드**만 수행 |
| KOI 서버 저장 | KOI 자체 정책. **RTMC 연동과 무관** |
| RTMC ↔ KOI API | **상태·URL·알림톡 발송 요청**만. 상담기록 payload **전송·적재 없음** |
| RTMC가 보관하는 데이터 | 상태, 예약·확정·완료 일시, 담당 `staff_id` 등 **연계 메타** |
