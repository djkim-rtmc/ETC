## 4. 이번 전달분 반영 사항 (2026.09.18)

### 4.1 접종자 — Case A 신청 흐름

| 단계 | 화면 (`data-screen`) | 동작 |
|---|---|---|
| 1 | `result` | 자가체크 결과 → **비대면 상담 신청하기** |
| 2 | `doctor` | **의료진 선택** — 카드 탭 시 선택만 반영 (화면 이동 없음) |
| 3 | `doctor` | **다음** 버튼 — 의료진 선택 후 활성화 → 탭 시 일정 화면 이동 |
| 4 | `schedule` | **상담 일정 선택** — 일자·시간 선택 후 **비대면 상담 신청하기** |
| 5 | (확인 모달 → 홈) | 신청 완료 · 상태 **예약대기** |

**의료진 카드 UI**

- 미선택: 흰 배경 · 회색 테두리 · 연한 파란 아바타
- 선택: 연한 하늘색 배경(`#f8fbff`) · 파란 테두리 · **파란 아바타 + 흰 글자**
- 우측 `>` / 「선택됨」 뱃지 **없음** (카드 스타일만으로 선택 표시)
- 일정 선택 화면 상단 선택 의료진 카드 = **동일 선택 스타일** (`provider-card selected`)

**의료진 리스트**

- 최대 **3명 노출** + 스크롤 (목업 6명 데이터)

### 4.2 신청 가능 기간 카드 (`booking-window`)

의료진 선택·기간 만료 화면 공통 컴포넌트.

| 요소 | 설명 |
|---|---|
| 라벨 | **신청 가능 기간** |
| 메인 | `{마감일시}까지 신청 가능` 또는 만료 시 `{마감일시}에 신청 마감` |
| 서브 | `{N}차 자가체크 · {응답일시} 응답 · {N+1}차 자가체크 종료(접종 후 {H}시간) 전까지 …` |

- 의료진 선택: 카드는 리스트 **아래** 고정
- 기간 만료: `is-expired` 스타일(노란 톤) · hero 아래 동일 카드

### 4.3 신청 가능 기간 — 비즈니스 로직 (구현 참고)

접종 시각(`mockVaxAt`) 기준 **접종 후 경과 시간**으로 자가체크 구간을 나눈다.

| 자가체크 차수 | 접종 후 구간 |
|---|---|
| 1차 | 3 ~ 48시간 |
| 2차 | 48 ~ 72시간 |
| 3차 | 72 ~ 168시간 |
| 4차 | 168시간 이후 (종료 없음) |

**상담 신청 가능 조건**

- **N차 자가체크 완료** 후
- **(N+1)차 자가체크 종료 시각(= 해당 구간 end 시간) 전**까지 신청 가능
- 4차 완료 후: **기한 없음**

**마감 시각 계산 (목업 JS)**

```javascript
// N차 완료 → (N+1)차 구간 end(시간)를 consultDeadlineHour로 사용
deadline = mockVaxAt + deadlineHour * 3600000
// 서브텍스트: mockSelfCheckAtByRound[N] = N차 자가체크 응답 시각
```

> 실제 개발 시 `mockVaxAt` → 접종일시, `mockSelfCheckAtByRound` → 자가체크 응답 API, `completedCheckRound` → 사용자 완료 차수로 치환

### 4.4 기간 만료 화면 (`booking-closed`)

| 요소 | 내용 |
|---|---|
| 제목 | 상담 신청 기간이 지났습니다 |
| 설명 (2줄) | `지금은 신청할 수 없습니다.` + 줄바꿈 + `{N+1}차 자가체크를 완료하면 다시 신청할 수 있습니다.` |
| 하단 카드 | 신청 가능 기간 · `{일시}에 신청 마감` + 서브 안내 |
| CTA | **자가체크 결과로** (iframe) / **홈으로** (레거시 tele) |

진입: `bookingMode === "closed"` 또는 우측 **기간 만료** 선택

### 4.5 용어 — 「신청」 vs 「예약」

| 구분 | 표기 |
|---|---|
| **접종자 신청 UX** (선택·일정·기간 안내) | **신청** — 예: 신청 가능 기간, ~까지 신청 가능, 신청 마감 |
| **상태 코드·의료진 화면** | **예약** 유지 — 예: 예약대기, 예약확정, 예약관리, 예약 확정 |

접종자가 일정을 고르는 단계는 「신청」 톤, 확정 이후 운영 상태는 기존 「예약」 상태 체계를 따른다.

### 4.6 의료진 — 기타 반영

| 항목 | 내용 |
|---|---|
| 접종자 상세 **상태** 행 | `예약대기 · 2026.09.18 10:22` 형식 (상태 + 전환 일시) |
| 대시보드 파이프라인 | **상담접수** 제거 · 취소는 **상담불참 / 상담취소** 분기 |
| 레거시 tele 중간 화면 | `mid-*`, `exc-*` 등 삭제 · 당일 입장 핵심만 유지 |

## 9. 목업 vs 실제 개발

| 목업 | 실제 개발 |
|---|---|
| `_proposal_decoded.html` 단일 HTML + 인라인 JS | React/Vue 등 프론트 + API |
| `mockVaxAt`, `mockSelfCheckAtByRound` | 접종·자가체크 API |
| `completedCheckRound`, `bookingMode` 셀렉트 | 서버 계산 + 진입 가드 |
| base64 iframe 임베드 | 유저웹 라우트 `/teleconsult/...` |
| 의료진·접종자 탭 전환 | 별도 앱/도메인 |

### 9.1 개발 시 필수 구현 체크

- [ ] N차 자가체크 완료 + (N+1)차 구간 end 전 신청 가능 검증 (서버)
- [ ] 기간 만료 시 `booking-closed` equivalent 라우트/화면
- [ ] 의료진 선택 → 다음 분리 (선택 상태만 저장, 다음에서 schedule 이동)
- [ ] 신청 가능 기간 카드 — 응답 시각·마감 시각 API 연동
- [ ] 신청 완료 → **예약대기** 상태 전이 (Case A)
- [ ] 용어: 접종자 신청 UX는 **신청**, 상태는 **예약대기/예약확정** 유지

### 9.2 목업 한계 (의도적 생략)

- 실제 WebRTC·STT·SOAP 엔진
- 알림톡 발송 API 연동
- 가족 계정·권한
- 일정 변경·URL 만료 예외 상세

## 10. 데모 시나리오 (개발팀 확인용)

### A. 정상 신청

1. 접종자 탭 → iframe **5. 자가체크 결과**
2. **비대면 상담 신청하기** → 의료진 선택
3. 의료진 카드 탭 → 선택 스타일 확인 → **다음** 활성화
4. **다음** → 일정 선택 → 일자·시간 → **비대면 상담 신청하기**
5. 홈 **예약대기** 상태 확인

### B. 신청 기간·만료

1. 우측 **완료 자가체크** 2차·3차 변경 → 신청 가능 기간 문구·마감 시각 변경 확인
2. **신청 가능 → 기간 만료** → `booking-closed` 화면 · 2줄 안내 · 신청 마감 카드

### C. 의료진 확정

1. 의료진 탭 → 예약관리 → **예약대기** → **예약 확정**
2. 접종자 홈 **예약확정** 전환 확인
