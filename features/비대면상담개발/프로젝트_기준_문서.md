## 1. Cursor + GitHub에서 시작하는 순서

1. GitHub에서 이 저장소를 **Clone**합니다.
   ```powershell
   git clone <저장소 URL>
   cd 원격진료_RTMC자체개발
   ```
2. **Cursor** → **File → Open Folder**로 클론한 폴더를 엽니다. (Cursor Project를 쓰는 경우 동일 폴더를 Project 루트로 연결)
3. Node.js 설치 여부 확인 (접종자 iframe 재인코딩 시 필요).
   ```powershell
   node -v
   ```
4. 브라우저로 `04_화면목업/RTMC_원격진료_자체서비스_목업.html`을 열어 목업이 뜨는지 확인합니다.
5. 새 Cursor 대화 시작 시:
   > `프로젝트_기준_문서.md`를 먼저 읽고 이어서 작업해줘. 답변은 한국어로.

> **Cursor 대화 기록은 Git에 포함되지 않습니다.** 과거 사용자 요청 원문은 [`00_인수인계/대화_요청이력.md`](./00_인수인계/대화_요청이력.md)에 있습니다.

## 2. 프로젝트 한 줄 요약

자가체크(접종 후 이상반응 체크) 결과를 바탕으로 **접종자와 의료진을 연결하는 비대면 상담 서비스**를, 외부 업체(KOI) 연동 없이 **RTMC가 자체 개발**하기 위한 기획·화면 목업 작업입니다.

- **접종자(유저웹)**: 신청 → 의료진·일정 선택 → 당일 상담실 입장 → 화상 상담
- **의료진(VD-IMS)**: 자가체크 조회 → 상담 요청·확정 → 스케줄 관리 → 상담실 진행
- **플랫폼**: 상태 전이·알림톡·WebRTC 상담실·메타데이터만 보관 (상담기록 본문은 서버에 저장하지 않고 로컬 다운로드만)

## 4. 통합 목업 구조 (가장 중요)

`RTMC_원격진료_자체서비스_목업.html` 한 파일 안에 세 영역이 들어 있습니다.

| 영역 | 위치 | 고치는 방법 |
|---|---|---|
| 의료진 VD-IMS 전체 | 통합 HTML 본문 | 통합 HTML을 직접 수정 |
| 접종자 유저웹 (홈·메뉴·허브·상세·결과·의료진 선택·일정 선택·기간 만료) | `PATIENT_PROPOSAL_BASE64` 상수에 **base64로 인코딩된 iframe** | `_proposal_decoded.html` 수정 후 재인코딩 |
| 접종자 당일 흐름 (동의 → 기기 확인 → 대기 → 상담 중 → 완료, 기간만료 칩) | 통합 HTML 안 `#patientLegacyView` (`patientNavMode="tele"`) | 통합 HTML을 직접 수정 |

### 4.1 접종자 iframe 화면 수정 절차

통합 HTML에서 iframe 내용을 검색하면 base64 문자열만 보이므로, 반드시 편집 원본을 거쳐야 합니다.

```powershell
cd 04_화면목업
node _decode_proposal.js     # (선택) 통합 HTML → _proposal_decoded.html 추출
# _proposal_decoded.html 수정
node _encode_proposal.js     # _proposal_decoded.html → 통합 HTML에 다시 넣기
```

- 2026.10.22 확인 기준, `_proposal_decoded.html`과 통합 HTML 안의 내용은 **일치**합니다.
- 통합 HTML을 다른 곳에서 고쳤을 가능성이 있으면, 편집 전에 `_decode_proposal.js`를 먼저 실행해 원본을 최신화하세요. 그렇지 않으면 `_encode`할 때 그 변경이 덮어써집니다.
- 접종자 용어·정책을 바꿀 때는 **iframe과 레거시 당일 흐름 양쪽**을 같이 고쳐야 합니다. (예: 신청 가능 기간 문구는 `getBookingWindowCopy`(iframe)와 `patientGetBookingWindowCopy`(통합 HTML) 두 곳에 있습니다)

### 4.2 목업 확인 방법

- 상단 역할 전환: **의료진 / 접종자 / 비대면 상담**
- 접종자 iframe 우측 컨트롤(목업 전용)
  - **상태**: 홈 상태영역 (미신청 · 예약대기 · 예약확정 · 상담중)
  - **신청 가능**: 신청 가능 / 기간 만료
  - **완료 자가체크**: 1~4차 → 신청 가능 기간 문구와 마감 시각이 바뀜

### 5.2 상태 체계

- **상담접수 상태는 삭제**
- **상담요청**: 의료진이 먼저 제안해서 알림톡을 보낸 건 (접종자 일정 미선택)
- **예약대기**: 접종자가 직접 신청한 건 + 의료진 제안 후 접종자가 일정을 고른 건
- **상담취소**는 **의료진 취소 / 접종자 취소**로 구분
- 대시보드 파이프라인: `상담요청 → 예약대기 → 예약확정 → 상담중 → 상담완료`, 종료 분기 `상담불참` · `상담취소`
- 상태 9종의 상세 정의는 `01_프로세스/RTMC_비대면상담_자체개발_정리.md` 3절

### 5.3 정책

| 정책 | 내용 |
|---|---|
| 상담 대상 | **자가체크 기록이 있는 사람만** 상담 가능 |
| 스케줄 단위 | 의료진 등록·접종자 선택 모두 **30분 단위** |
| 상담실 입장 | 상담 시작 **15분 전**부터 의료진·접종자 모두 입장 버튼 활성 |
| 상담실 입장 버튼 | 상담중 = **핑크 + 깜빡임 효과** / 접종자 입장 완료·시작 대기 = 핑크(효과 없음) / 접종자 미입장 = 회색 |
| 접종자 카메라·마이크 | **반드시 사용** — 끄는 기능 없음, 기기 확인 화면에서 정상 동작 확인 후 진행 |
| 의료진 카메라·마이크 | 사용 여부 선택 가능, 켜짐/꺼짐 상태 표시 |
| 신청 가능 기간 | 아래 5.4 |

### 5.4 신청 가능 기간 로직 (마지막 작업 주제)

자가체크 차수별 진행 가능 구간(접종 시각 기준):

| 차수 | 구간 |
|---|---|
| 1차 | 접종 후 3 ~ 48시간 |
| 2차 | 48 ~ 72시간 |
| 3차 | 72 ~ 168시간 |
| 4차 | 168시간 이후 (종료 없음) |

**N차 자가체크를 완료한 접종자는 (N+1)차 구간이 끝나기 전까지 상담 신청 가능.** 4차 완료 후는 기한 없음.

- 의료진 선택 화면 하단 **신청 가능 기간** 카드: `2026.09.18 (금) 16:51까지 신청 가능` / `1차 자가체크 · 2026.09.17 (목) 20:40 응답 · 2차 자가체크 종료(접종 후 72시간) 전까지 …`
- 기간이 지나면 **기간 만료 화면**: 「지금은 신청할 수 없습니다. / 2차 자가체크를 완료하면 다시 신청할 수 있습니다.」 + 노란 톤 카드 `{일시}에 신청 마감`
- 목업 변수 → 실제 개발 치환: `mockVaxAt`(접종일시), `mockSelfCheckAtByRound`(차수별 응답 시각), `completedCheckRound`(완료 차수), `bookingMode`(서버 판단)
