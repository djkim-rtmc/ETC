# AI 기반 백신 이상반응 돌봄케어 서비스 — 프로세스 확정(v4)

> 개발상세계획서(2026-07-03)의 서비스 흐름을 유지하고, 이후 확정된 운영 방식으로 고친 문서이다.
>
> **v4에서 바꾼 내용**
> - 서비스 명칭은 **비대면 상담**이다.
> - 위험도 결과는 **분류**이다. 예측이라는 말은 쓰지 않는다.

---

## 1. 확정된 프로세스 (8단계)

```
① RTMC 유저웹 회원가입(SNS/본인인증)
   ↓
② 접종기관 방문 + 자사 디바이스(RTMC-TAB) QR·바코드 스캔 → 접종완료
   ↓
③ VD-IMS 내 접종내역 확인
   ↓
④ 자가체크 1차(3h): 증상체크 + 기저질환
   자가체크 2~4차(48h·72h·168h): 증상체크
   ↓
⑤ 회차마다 AI 위험도 분류(Level 1~4)와 판정 근거
   ↓
⑥ Level 3·4 의료진 알림
   ↓
⑦ 비대면 상담 — 양방향(의료진 제안 · 접종자 신청)
   화면 메뉴명: 원격 상담
   ↓
⑧ 상담 상태·상담 내용 정리 → VD-IMS 돌봄 이력 집계
```

### 단계별 구체화

**① RTMC 유저웹 회원가입** — 담당: 리얼타임메디체크
- SNS 로그인 또는 본인인증으로 가입한다.
- 이 시점에는 건강정보를 받지 않는다. 계정 식별정보만 만든다.
- 가입이 끝나면 유저 ID를 발급하고, 이후 연동은 이 ID로 한다.

**② 접종정보 등록** — 담당: 접종기관 의료진 + 리얼타임메디체크(자사 디바이스)
- 대면 예진 내용은 접종기관 안에만 둔다. VD-IMS로 넘기지 않는다.
- 실증기관에 제공한 자사 디바이스(RTMC-TAB)에서 참여자 QR과 백신 바코드를 스캔한다.
- 접종정보(백신명·제조사·로트번호·접종기관·접종일시)는 VD-IMS에 직접 저장한다.
- 의료기관 진료기록 시스템과는 연동하지 않는다. 항목 관리는 데이터 항목 정의서로 한다.

**③ VD-IMS 내 접종내역 확인** — 담당: 리얼타임메디체크(VD-IMS)
- 참여자는 RTMC 유저웹에서 본인 접종내역(백신명·접종일시·접종기관)을 조회한다.

**④ 자가체크 4회** — 담당: 리얼타임메디체크(유저웹)
- 기준 시각은 해당 접종 시각이다.
- 1차 3시간~48시간, 2차 48시간~72시간, 3차 72시간~168시간, 4차 168시간 이후.
- 1차에서만 증상 체크와 함께 **기저질환**을 받는다. 2~4차는 증상 체크(서술형 포함)만 한다.
- 서술형 응답은 sLLM+RAG로 증상 대분류·세부증상·통증강도로 바꾼다. 증상 체계는 11개 대분류·52개 세부증상이다.
- 해당 회차 창이 아니면 그 회차 자가체크와 비대면 상담 신청 버튼을 열지 않는다.

**⑤ AI 위험도 분류** — 담당: 리얼타임메디체크 (학습·추론 인프라: 한림대 소형 AIDC)
- 매 회차, 그 시점까지 누적된 구조화 데이터로 Level 1~4를 분류하고 VD-IMS로 돌려준다.
- Level은 참고 분류이다. 진단명을 만들지 않고, 비대면 상담을 자동으로 시작하지 않는다.
- 접종 직후 대기실에서 생기는 급성 반응은 이 분류의 대상이 아니다. 분류는 1차 자가체크부터 적용한다.
- 모델 학습·검증·추론은 한림대학교 소형 AIDC에서 한다. 9월에 자원 협의를 마쳤고, 본학습·모델 이관 후 실시간 추론은 2026-10-19부터 적용한다.

**⑥ 의료진 알림** — 담당: 리얼타임메디체크(VD-IMS)
- Level 3·4이면 의료진에게 알리고 상담 대상 우선순위에 올린다.
- Level 1·2는 별도 알림 없이 관찰 안내로 둔다.
- 상담을 열지는 의료진 판단 또는 접종자 신청으로 정한다.

**⑦ 비대면 상담** — 담당: 리얼타임메디체크(VD-IMS·유저웹·화상상담실·알림톡)
- 의료진 제안과 접종자 신청을 모두 둔다. 접종자 신청은 Level과 관계없이, 해당 회차 결과 화면에서 한다.
- VD-IMS 메뉴명은 「원격 상담」이다. 의료진은 여기서 상태를 보고, 「원격 상담 접속하기」로 화상상담실에 들어간다.
- 화상상담실은 자체 구축(LiveKit)이며 별도 창으로 연다. 의료진은 VD-IMS의 AI 분석·자가체크 화면을 함께 본다.
- 알림톡은 리얼타임메디체크가 발송한다.
- 2026-10-06 통합테스트 후 운영 배포한다.

**⑧ 돌봄 이력 집계** — 담당: 리얼타임메디체크(VD-IMS)
- 상담 상태와 「상담 내용 정리」를 돌봄 이력으로 남긴다.
- 참여자 수, Level 3·4, 비대면 돌봄 건수, 만족도를 집계한다.
- 돌봄 건수는 같은 참여자를 실증 기간 중 한 번만 센다. 자동분류 건수는 자가체크 1회차의 분류 결과 1회를 1건으로 센다.

## 3. AI 분류

학습·검증·추론은 한림대 소형 AIDC에서 한다. 학습용으로 정제한 기존 이상반응 데이터는 15,000건이다.

| 순서 | 구성 | 하는 일 | 입력 | 출력 |
|---|---|---|---|---|
| ① | sLLM+RAG 구조화 | 서술형 응답을 정형 값으로 바꿈 | 서술형 텍스트 | 증상 대분류·세부증상·통증강도 |
| ② | Level 분류 | 그 회차까지 누적 데이터로 Level 1~4 분류 | 증상·통증강도·발생 회차(3·48·72·168h)·기저질환·연령 | Level 1~4 |
| ③ | 판정 근거 | 왜 그 Level인지 요인별로 보여 줌 | ②의 입력·출력 | 요인별 기여도 |
| ④ | 자체 성과검증 | 홀드아웃·교차검증으로 분류 결과를 점검 | 검증용 데이터 | 자체 검증 결과 |
| ⑤ | 연속 학습 | 실증 중 새로 쌓인 자가체크를 반영 | 신규 실증 데이터 | 재학습 모델 |

분류 모델은 XGBoost·LightGBM·Random Forest와 LSTM·GRU·Temporal Transformer를 결합하는 Hybrid AI를 전제로 한다. 임계치와 최종 알고리즘은 기존 자가체크 데이터로 맞춘다. 고정된 「몇 점이면 몇 Level」 표로 설명하지 않는다.

| Level | 의미 | 의료진 알림 | 비대면 상담 |
|---|---|---|---|
| 1 관찰 | 흔한 접종 후 반응 | 없음 | 접종자가 회차 창 안에서 신청할 수 있음 |
| 2 주의 관찰 | 경과를 더 봄 | 없음 | 동일 |
| 3 관리군 | 확인 권고 | 알림 | 의료진 제안 또는 접종자 신청 |
| 4 고위험군 | 의료진 확인 권고 | 알림 | 의료진 제안 또는 접종자 신청 |

1차 자가체크 전에는 기저질환이 없다. 그래서 1차 이전의 급성 반응은 접종기관의 현장 관찰로 다룬다.

성능 수치는 자체 검증 결과로만 제시한다. 공인기관 시험성적서는 이 프로세스의 산출물이 아니다.

## 4. 비대면 상담

운영 기관은 한국건강관리협회 강원도지부이다. 기관 안에 의료진 계정이 여러 개 있을 수 있다.

VD-IMS는 비대면 상담을 **요청 → 접수 → 진행 → 완료**로 운영한다. Level만으로 상담을 연결하지 않는다.

### 4.1 화면 상태

목록의 「원격 상담」열은 **최신 회차** 상태만 보여 준다. 새 회차 자가체크가 나오면 그 회차는 해당없음에서 다시 시작한다. 상세에서는 1~4차 이력을 칩으로 유지한다.

| 상태 | 의미 |
|---|---|
| 해당없음 | 그 회차에 상담이 없음 |
| 상담요청 | 의료진이 제안했고, 접종자가 아직 일정을 고르지 않음 |
| 상담접수 | 접종자가 의료진·일정까지 신청함. 확정 전 |
| 예약대기 | 의료진 제안 건에서 접종자가 일정을 고름. 의료진 확정 대기 |
| 예약확정 | 의료진이 확정함. 접속 주소가 생김 |
| 상담중 | 화상상담이 진행 중 |
| 상담완료 | 상담이 끝남 |
| 상담취소 | 확정 전 취소, 또는 의료진의 일정 취소 |
| 상담불참 | 의료진이 불참으로 처리 |

상담 요청은 **최신 회차**이면서 상태가 해당없음일 때만 연다.

### 4.2 두 가지 유입

**의료진 제안**  
자가체크 결과를 보고 상담이 필요하다고 판단하면 제안한다. 접종자에게 알림톡(예약 안내, 기관명)을 보내고, 접종자가 일정을 고르면 예약대기가 된다. 의료진이 확정하면 예약확정이다.

**접종자 신청**  
해당 회차 자가체크를 마쳤고, 그 회차 상담이 해당없음이며, 지금이 그 회차 가능 시간 안일 때만 「비대면 상담 신청하기」를 보여 준다. 이미 진행 중인 회차는 버튼 대신 상태 카드를 보여 준다. 신청 직후 상태는 상담접수이다. 의료진이 확정하면 예약확정이다.

1차에서 상담을 마친 뒤에도, 다음 회차 결과가 있고 그 회차 상담이 해당없음이면 그 회차에서 다시 신청할 수 있다.

```
자가체크 결과 + Level
    │
    ├─ 의료진 제안 → 상담요청 → 접종자 일정 선택 → 예약대기
    │
    └─ 접종자 신청 → 상담접수
              │
              ▼
         의료진 확정(확인) → 예약확정
              │  알림톡: 확정 일시 + 접속 주소
              │  당일 1시간 전 리마인드
              ▼
         상담중 (화상상담실 별도 창)
              │
              ▼
         상담완료 → 상담 내용 정리 저장, VD-IMS 돌봄 이력 반영
```

### 4.3 일정

- 예약 가능 일정은 **기관 단위**로 연다. 의료진이 제안한 경우에는 그 의료진을 기본 선택으로 두고, 같은 기관의 다른 예약 가능 의료진도 고를 수 있다.
- 같은 의료진은 같은 시각에 1건만 상담한다. 다른 의료진은 같은 시각에 각자 상담할 수 있다.
- 같은 슬롯을 나중에 고른 사람에게는 이미 예약된 시간임을 안내한다.
- 확정 전에는 같은 경로로 일정을 바꾸거나 취소할 수 있다.
- 확정할 때는 확인 단계를 둔다.
- 그 회차의 신청 가능 시간이 지나면 신청 버튼을 누르지 못하게 한다.

### 4.4 화상상담과 기록

- 의료진은 VD-IMS의 AI 분석·자가체크 화면과 화상상담 창을 함께 쓴다.
- 상담 기록은 SOAP 4칸이 아니라 **상담 내용 정리** 한 칸이다. 초안이 있으면 의료진이 검토한 뒤 저장한다.
- 진단·처방 문서로 남기지 않는다.

### 4.5 알림톡

발송 주체는 리얼타임메디체크이다.

| 구분 | 기준 |
|---|---|
| 예약 안내 | 의료진 제안 때 발송. 확정 전에는 의료진 이름 대신 **기관명**만 적는다 |
| 예약 확정 | 확정 일시와 상담 접속 주소를 넣어 발송 |
| 당일 리마인드 | 상담 1시간 전. 같은 접속 주소 |
| 상담 완료 | 완료 알림톡은 보내지 않음 |
| 불참·의료진 취소 | 예약 시각 자동 계산으로 바꾸지 않는다. 의료진이 상담실 또는 예약 관리에서 직접 처리한다 |

접종자가 먼저 신청한 건(상담접수)에는 신청 직후 예약요청 알림톡을 보내지 않는다. 확정 알림톡부터 보낸다.

### 4.6 주고받는 값

시스템 사이에는 유저 ID, Level, 신고 증상, 통증강도, 회차, 상담 상태, 확정 시각, 상담 내용 정리를 주고받는다. 이름·나이·전화번호는 상담 화면 구성에 필요하지 않으면 넘기지 않는다.

## 5. 개인정보·데이터 처리

### 5.1 정보의 성격

- 접종 이력, 기저질환, 이상반응 증상은 개인정보보호법상 민감정보(건강에 관한 정보)이다. 일반 동의와 따로 동의를 받는다.
- 실증에서 직접 모으는 정보는 진료기록이 아니라, 참여자가 접종 후 자신의 상태를 입력하는 **자가증상 라이프로그**이다. 사람 대상 개입연구나 진료기록 연구에 해당하지 않으므로 IRB 심의 **비대상**이다.
- 서비스 이용 전에 개인정보 처리, 서비스 이용, 제3자 제공, 민감정보 처리 동의를 받는다.
- 실증기관과는 개인정보 위수탁 근거를 갖춘다.

### 5.2 단계별 수집 항목

| 단계 | 수집 항목 | 수집 주체 | 구분 |
|---|---|---|---|
| ① 회원가입 | 본인인증 식별정보, 연락처 | 리얼타임메디체크 | 일반 개인정보 |
| ② 접종 등록 | 백신명·제조사·로트·접종기관·접종일시. 예진 내용은 기관 보관, VD-IMS 미연계 | 자사 디바이스 → VD-IMS | 접종정보는 일반. 예진 내용은 미수집 |
| ④ 자가체크 1차 | 증상, 통증강도, 기저질환, 서술형 | 참여자 입력(유저웹) | 민감정보 |
| ④ 자가체크 2~4차 | 증상, 통증강도, 서술형 | 참여자 입력(유저웹) | 민감정보 |
| ⑤ 분류 결과 | Level, 판정 근거 | 리얼타임메디체크 | 산출 정보 |
| ⑦~⑧ 비대면 상담 | 유저 ID, Level, 신고 증상, 예약·상담 상태, 상담 내용 정리 | 리얼타임메디체크 | 상태·상담 기록 |

기저질환은 참여자가 1차 자가체크에서 직접 입력한다. 병원 예진 정보를 끌어오지 않으므로 입력 정확도 안내를 1차 화면에 둔다.

### 5.3 처리 원칙

1. 시스템 간 키는 ①에서 발급한 유저 ID이다. 실명·연락처는 회원 정보에 둔다.
2. 사용 목적은 이상반응 모니터링, 돌봄 연계, 분류 모델 개선으로 한정한다.
3. 주민등록번호 등 운영에 필요 없는 항목은 받지 않는다.
4. 상담 내용 정리는 비대면 상담 기록으로만 쓰고, 진단·처방 기록으로 쓰지 않는다.
5. 한림대 소형 AIDC에 학습·추론을 두는 경우와 실증기관 위수탁은 계약에 목적 외 처리 금지, 보호조치, 재위탁 제한, 파기, 관리·감독을 적는다.

### 5.4 안전성 확보조치

| 구분 | 조치 | 상태 |
|---|---|---|
| 기술적 | 통신 구간 TLS, AIDC 연계는 VPN 또는 전용 접속 | 반영 |
| 기술적 | 저장 데이터 암호화 | AIDC 저장 정책에 맞춤 |
| 기술적 | 의료진·관리자 권한 분리 | 반영 |
| 기술적 | 접속기록, 로그인 이력, 2차 인증 | 개발 반영 중 |
| 관리적 | 개인정보 처리방침 공개 | 개정 약관 홈페이지 공시(2026-10-07) |
| 관리적 | 개인정보 보호책임자 지정 | 지정 유지 |
| 물리적 | 연산 자원 접근 통제 | 한림대 소형 AIDC 정책 |

보안 설계·운영기준은 보안 컨설팅 2단계(9~10월)와 맞춰 정비한다.

### 5.5 보유와 파기

- 보유 기간과 파기 절차는 동의서와 데이터 항목 정의서에 적는다.
- 연속 학습에 남기는 데이터는 식별할 수 없게 처리한 뒤 보관한다.

### 5.6 이후 검토

- Level 분류가 판단 보조를 넘지 않도록 화면 문구를 유지한다. 소프트웨어 의료기기 해당 여부는 정식 전환 전에 다시 본다.
- 정식 서비스로 바꿀 때는 개인정보 영향평가를 권장한다.
