# 원격진료 연계 요청 사양서 (코이헬스케어 귀중)

> 발신: ㈜리얼타임메디체크  
> 과제: AI 기반 백신 이상반응 돌봄케어 서비스 실증(강원 AX 소형 데이터센터 공동활용 지원사업)  
> 기준: 2026.08.27 실무 협의 + RTMC 운영 방향  
> 요청 범위: 비대면 상담 예약 웹·스케줄·화상상담, 상담 대화 AI 텍스트 전환·RTMC 전달, 알림톡 발송 요청, 상태(요청·접수·진행·완료) 콜백

---

## 1. 연동 목적 및 역할

㈜리얼타임메디체크는 예방접종 후 이상반응을 자가체크로 모니터링하고, AI가 심각도를 Level 1~4로 **참고 분류**하는 서비스(VD-IMS)를 운영합니다. Level은 의료진 판단 보조 정보입니다. **원격진료 대상은 Level과 무관**합니다.

| 구분 | RTMC | KOI |
|---|---|---|
| 자가체크 결과에서 원격진료 신청 | 유저웹에서 신청 가능하도록 개방 | 예약 웹·스케줄 제공 |
| 의료진 제안(알림톡) | **알림톡 발송** | 발송 요청 + 예약 웹 URL 제공 |
| 예약 확정 알림톡 | 확정 일시 + 상담 접속 링크 발송 | 접속 링크 제공 |
| 화상상담·대화 텍스트 | 환자정보(AI/자가체크) 화면 제공 | 별도 창 상담, 대화 AI 텍스트 전환·저장 후 RTMC 전달 |
| 상태 | VD-IMS에서 **요청 → 접수 → 진행 → 완료** 운영 | 상태·대화 텍스트 콜백 |

연락처(전화번호)는 기본 전달하지 않습니다. 필요 시 병원 의료진이 VD-IMS에 보유한 번호로 직접 통화합니다.

---

## 2. 업무 케이스 (양방향)

### Case A. 의료진 제안형
의료진이 자가체크/이상반응 결과를 확인 → 상담 필요 판단 → 원격진료 요청  
→ **KOI가 알림톡 발송을 요청** → **RTMC가 알림톡 발송**(본문: KOI 예약 웹 URL)  
→ 접종자가 일정 선택(접수) → 확정 → 진행 → 완료

### Case B. 접종자 신청형
접종자가 자가체크 결과에서 원격진료 신청(위험군·Level 무관)  
→ 의료진 선택 및 해당 의료진 가용 일정 노출 → 접수 → 확정 → 진행 → 완료

공통: 확정 전까지 동일 링크로 일정 변경·취소 가능. 확정 시 확인 팝업. 확정 알림톡에 **일시 + 상담 접속 URL**.

## 3. 요청 기능

| No | 기능 | 상세 | 주체 |
|---|---|---|---|
| 1 | 접종자 예약 웹 URL | 의료진 선택, 선택 의료진의 가용 슬롯만 노출 | KOI |
| 2 | 의료진·기관 스케줄 | 의료진은 본인 슬롯 등록, 기관은 전체 조회. 같은 계정 동시간 1건, 다른 계정은 동시간 가능 | KOI |
| 3 | 알림톡 발송 요청 | 예약요청·예약확정·당일리마인드. RTMC가 실제 발송 | KOI 요청 / RTMC 발송 |
| 4 | 세션 URL | 확정 시점에 상담 접속 URL 제공. 확정 알림톡에 포함 | KOI |
| 5 | 상태 콜백 | 요청 · 접수 · 진행 · 완료 · 불참 · 취소 | KOI → VD-IMS |
| 6 | 동시 예약 충돌 | 같은 슬롯 중복 시 후순위에게 「이미 예약된 시간」 | KOI |
| 7 | 확정 전 변경·취소 | 동일 URL 재접속 | KOI |
| 8 | 화상상담(별도 창) | 의료진은 RTMC 환자정보 화면과 동시 사용 | KOI |
| 9 | 상담 대화 AI 텍스트 전환 | 원격진료 종료 후 대화 내용을 AI로 텍스트 전환·저장 → RTMC 전달 | KOI |
| 10 | 불참 | 예약시각 30분 경과 시 불참. 약 25분 전후 화면 경고·재예약 안내는 웹 | KOI |

완료 알림톡은 우선 발송하지 않습니다.

## 4. 데이터 인터페이스 (협의 초안)

### 4.1 요청 이벤트 (VD-IMS → KOI)

```json
{
  "case_id": "유저 ID",
  "request_type": "staff_propose | patient_apply",
  "level": 3,
  "reported_symptom": "전신증상-피로",
  "pain_score": 4,
  "onset": "48시간",
  "timestamp": "2026-08-27T15:00:00+09:00"
}
```

`level`은 참고 값입니다. 접수 거절 조건으로 쓰지 말아 주세요.

### 4.2 알림톡 발송 요청 (KOI → RTMC)

의료진 제안(Case A) 및 확정·당일 리마인드에 사용합니다.

```json
{
  "case_id": "유저 ID",
  "alimtalk_type": "예약요청 | 예약확정 | 당일리마인드",
  "booking_url": "https://...",
  "session_url": "https://...",
  "scheduled_at": "2026-08-28T14:00:00+09:00"
}
```

- 예약요청: `booking_url` 필수  
- 예약확정: `scheduled_at` + `session_url` 필수  
- 당일리마인드: 추가 검토(긍정)

### 4.3 상태·결과 콜백 (KOI → VD-IMS)

```json
{
  "case_id": "유저 ID",
  "consult_status": "요청 | 접수 | 진행 | 완료 | 불참 | 취소",
  "consult_channel": "영상 | 채팅 | 전화",
  "scheduled_at": "2026-08-28T14:00:00+09:00",
  "consulted_at": "2026-08-28T14:10:00+09:00",
  "followup_action_category": "경과관찰 안내 | 의료기관 방문 권고 | 응급 대응",
  "consult_transcript": "AI로 텍스트 전환된 원격진료 대화 내용"
}
```

원격진료 대화는 KOI가 AI로 텍스트 전환·저장한 뒤 RTMC로 전달합니다. 진단명·처방 전문은 KOI(의료기관)가 보관하며 콜백에 넣지 않습니다.

---

## 5. 개인정보

- 유저 ID 제공은 가능합니다.  
- 이름·나이 등 직접식별정보는 제3자 제공 동의 및 처리·파기 정책을 RTMC가 검토한 뒤 범위를 확정합니다.  
- 구현에 필요한 **최소 정보만** 연동합니다.  
- 예약 화면을 VD-IMS에 둘지·KOI 화면으로 둘지에 따라 전달 항목이 달라질 수 있습니다.

---

## 6. 보안·인증

- TLS 필수, 가능하면 VPN 등 추가 채널  
- OAuth 2.0 또는 mTLS  
- 유저 ID 기준, 최소 식별정보

---

## 7. 계약 시 명시 요청

- 책임 분계(API 오류, 미배정, 동시 예약 충돌)  
- 개인정보 처리위탁(제26조) 또는 제3자 제공 해당 유형  
- 진료기록(진단·처방)은 귀사 보관. 상담 대화 AI 텍스트 전환본은 RTMC로 전달  
- 원격의료 법적 근거  
- 보유·파기 기한
