# VD-IMS · 유저웹 — 전체 흐름과 로직

한 장으로 이 서비스가 **무엇을 하고, 누가 결정하고, 데이터가 어떻게 흐르는지**를 정리한 문서입니다.  
화면 목업: `개발전달/VDIMS_화면목업.html`

---

## 1. 이 서비스가 하는 일

예방접종 후 접종자가 **자가체크**를 올리면, AI가 심각도를 **Level 1~4로 참고 분류**합니다.  
의료진은 그 결과를 보고 관찰하거나 **원격진료**를 제안할 수 있습니다.  
접종자도 원하면 원격진료를 신청할 수 있습니다.  
실제 화상·상담은 연계기관(코이헬스케어)이 하고, 상담 종료 후 **대화 내용을 AI로 텍스트 전환·저장하여 RTMC로 전달**합니다. VD-IMS는 **요청 → 접수 → 진행 → 완료** 상태를 운영합니다. 알림톡은 우리가 발송합니다. 진단·처방은 KOI가 보관합니다.

```
가입 → 접종 → 자가체크(4회)
         → AI가 Level 분류 + 근거
         → 의료진 확인 / (선택) 원격진료
         → 일정 확정 시 세션 URL
         → 진료 → 완료(상태만 기록)
```

## 2. 등장하는 시스템과 역할

| 시스템 | 누가 쓰나 | 역할 |
|---|---|---|
| **유저웹**(접종자) | 접종자 휴대폰 | 자가체크 결과에서 원격진료 신청(전 Level) |
| **VD-IMS**(의료진 웹) | 병원 의료진 | 자가체크 목록·상세, AI 분석, 원격진료 상태(요청·접수·진행·완료), 알림 |
| **연세대 AI** | API | 서술 구조화, Level 판정, SHAP 근거. 학습·추론은 한림대 AIDC **H100** 사용 |
| **원격진료 연계기관(KOI)** | 의료기관 | 예약 웹 URL, 의료진·기관 스케줄, 화상상담, 대화 AI 텍스트 전환·RTMC 전달, 상태 콜백. 의료진 제안 시 알림톡 발송 요청 |
| 알림톡 | RTMC 발송 | 예약요청(KOI URL) · 확정(일시+접속 URL) · 당일 리마인드. 완료 톡은 제외 |

계정: 의료진은 개인 계정(목업: 김의료 / 이의료). 원격진료 **목록은 병원 공용**, **한 건의 일정은 의사 한 명만** 담당합니다.

## 3. 처음부터 끝까지 시간 순

```
① 유저웹 가입 (본인인증)
② 병원 접종 (예진은 병원만, VD-IMS로 안 넘김)
③ 접종 정보가 VD-IMS에 붙음
④ 자가체크
     1차  접종 후 3시간   + 기저질환·알레르기
     2차  48시간
     3차  72시간
     4차  168시간(7일)
⑤ 매 회차마다 연세대 AI
     서술 → 증상·점수  →  Level 1~4 + 근거
⑥ Level 3·4면 의료진 알림 (1·2는 알림 없음)
⑦ 원격진료는 신청/제안이 있을 때만 (전 Level 신청 가능)
     A. 의료진 제안: KOI가 알림톡 발송 요청 → RTMC가 알림톡 발송(예약 웹 URL)
     B. 접종자 신청: 자가체크 결과에서 신청
⑧ 요청 → 접수(일정 선택, 확정 전 변경·취소) → 확정(확인 팝업)
⑨ 확정 알림톡(일시+접속 URL) → 진행(KOI 별도 창) → 완료
     불참: 예약시각 30분 경과. 완료 알림톡은 없음
```

**접종 직후(대기실)** 이상반응은 이 AI 분류 대상이 아닙니다. 병원 현장 관찰입니다. AI는 **1차 자가체크(3시간)부터** 돌아갑니다.

## 4. AI Level — 기준과 방법

### 4.1 결과 이름

| Level | 의미 | 알림 |
|---|---|---|
| 1 관찰 | 흔한 접종 후 반응 | 없음 |
| 2 주의 관찰 | 조금 더 지켜봄 | 없음 |
| 3 관리군 | 확인 권고 | 의료진 알림 (노란 점) |
| 4 고위험군 | 의료진 확인 권고 | 의료진 알림 (빨간 점) |

Level은 **진단이 아닙니다.** 원격진료를 자동으로 시작하지도 않습니다.

### 4.2 분류 방법 (AI 2단계)

```
자가체크 문장·체크
    │
    ▼
[모델 ① 구조화]  sLLM + RAG
    증상 11개 대분류 + 세부증상 + 통증 1~5
    │
    ▼
[모델 ② 분류]  그 회차까지 누적 데이터
    Level 1 / 2 / 3 / 4
    │
    ▼
[모델 ③ 설명]  SHAP 등
    “숨참 4점이 평균보다 높다” 같은 근거 %
```

알고리즘은 연세대가 정합니다. 개발상세계획서는 Hybrid AI(XGBoost·LightGBM·Random Forest + LSTM·GRU·Temporal Transformer)와 sLLM+RAG, SHAP를 전제로 합니다. **몇 점이면 몇 레벨인지** 고정 표는 없고, 기존 자가체크 약 1.5만 건으로 맞춥니다.  
학습·검증·추론 GPU는 **한림대 AIDC가 제공하는 H100**을 연세대가 사용합니다.

### 4.3 모델이 보는 데이터

- 증상 종류·통증 강도  
- 회차(3·48·72·168시간)  
- 1차에서 받은 기저질환·알레르기  

학습 감: 기존 자가체크 약 **1.5만 건** + 실증(약 200명×4회).

### 4.4 화면에 붙는 것

의료진 상세 **AI 분석 결과** 탭: Level, 요약 문장, 요인 기여도, 같은 그룹 평균 비교, 회차별 Level 변화.

## 5. 원격진료 로직 (2026.08.27 협의)

VD-IMS 운영 상태: **요청 → 접수 → 진행 → 완료**. 예약 웹·화상·대화 텍스트 전환은 KOI. 알림톡은 RTMC.

### 5.1 두 가지로 시작, 한 줄로 모임

**A. 의료진이 먼저**  
자가체크 상세를 보고 원격진료 요청  
→ KOI가 알림톡 발송을 요청 → **RTMC가 알림톡 발송**(KOI 예약 웹 URL)  
→ 접종자가 일정 선택(접수) → 확정(확인 팝업) → 진행 → 완료

**B. 접종자가 먼저**  
자가체크 결과 **원격진료 신청하기**(모든 Level) → 의료진 선택 → 그 의료진 가용 일정만 노출  
→ 접수 → 확정 → 진행 → 완료

```
요청
    → 접수(일정 선택·가예약)   ※ 확정 전: 같은 링크로 변경·취소
    → 확정(확인 팝업)          ※ 이때 상담 접속 URL, 확정 알림톡
    → 진행(KOI 별도 창 + RTMC 환자정보)
    → 완료(대화 AI 텍스트 전환·저장 후 RTMC 전달)
```

같은 의료진 계정은 동시간 1건. 다른 의료진은 동시간 가능. 슬롯 충돌 시 후순위에게 「이미 예약된 시간」.

### 5.2 상태

| 상태 | 뜻 | 누가 만드나 |
|---|---|---|
| (없음) | 원격진료 없음 | 기본 |
| 요청 | 의료진 제안 또는 접종자 신청 | RTMC / KOI |
| 접수 | 일정 선택·배정 | 접종자 또는 운영 |
| 진행 | 화상상담 시작 | KOI 콜백 |
| 완료 | 종료 | KOI 콜백 |
| 불참 | 예약시각 30분 경과 | KOI / 운영 |
| 취소 | 확정 전 취소 | 접종자 또는 의료진 |

**담당 잠금**: 그 건을 잡은 의사만 처리. 다른 의료진 화면에서는 액션이 안 보입니다.

**URL 시점**: 확정할 때 상담 접속 URL이 생깁니다. Level이 나왔다고 세션을 만들지 않습니다. 예약 요청 알림톡에는 **예약 웹 URL**, 확정 알림톡에는 **접속 URL**.

### 5.3 유저웹 버튼 자리

신청 전에는 버튼 **원격진료 신청하기**(모든 Level).  
신청 후에는 그 자리가 상태로 바뀝니다.

| 상태 | 버튼 자리 |
|---|---|
| 미신청 | 원격진료 신청하기 |
| 요청 | 요청 (일정 선택 안내) |
| 접수 | 접수 + 선택 일시 (확정 전 변경·취소 가능) |
| 진행 | 진행 + 접속하기 |
| 완료 | 완료 |
| 불참 | 불참 (재신청 가능 여부는 운영 정책) |
| 취소 | 다시 신청하기 |

의료진 선택·일정 선택은 **바텀시트**. 오늘 이전, 스케줄 없는 날, 슬롯이 다 찬 날은 달력에서 고를 수 없습니다.

## 6. 화면별 로직 (의료진)

```
알림 ─클릭─→ 상세 (AI 탭 열린 상태)
자가체크 목록 ─클릭─→ 상세 (원격진료 탭)
원격진료 큐 ─상세보기─→ 같은 상세
```

**자가체크 목록**  
기간·키워드 + AI Level 다중필터 + 원격진료 상태 다중필터.  
이름 두 번째 글자 마스킹. 회차 필터 없음.

**상세**  
탭: 자가체크 비교(1~4차) / 만족도 / AI 분석 / 원격진료.  
원격진료 탭: 요청 메시지·확정 메시지. 접종자가 먼저 신청했으면 요청 메시지 비활성. 완료·타인 담당이면 요청·확정·접속 숨김.

**원격진료 큐**  
KPI(요청·접수·진행·완료)로 목록 필터.  
확정 일정은 오늘·내일·모레, 하루 3건+더보기.  
목록 10건+더보기. 카드에서 확정하지 않고 상세로만 감.

**알림**  
행 전체 클릭. 점만 표시(4=빨강, 3=노랑).  
세션 시작·완료 알림은 없음.

## 7. 데이터가 도는 순서

```
접종자 앱/유저웹
    자가체크 저장
         │
         ▼
    연세대 API  (구조화 + Level + SHAP)
         │
         ▼
    VD-IMS 저장, 목록·상세·유저웹 결과 반영
         │
    Level 3·4 → 의료진 알림
         │
    (선택) 원격진료
         ├─ 의료진 제안: KOI 알림톡 요청 → RTMC 발송(예약 웹 URL)
         └─ 접종자: 자가체크 결과에서 신청
         │
    요청 → 접수 → 확정 ──► KOI 세션 URL
         │
         ▼
    확정 알림톡(일시+접속 URL)
         │
         ▼
    진행(KOI 별도 창) → 완료/불참 콜백 + 상담 대화 AI 텍스트
```

전화번호는 연계기관에 안 넘깁니다. 필요하면 의료진이 VD-IMS에 있는 번호로 직접 겁니다.

## 8. 한 장 요약

1. **자가체크**가 들어오면 **AI가 Level을 붙인다.**  
2. **Level 3·4**만 의료진 알림. 1·2는 조용히 결과만.  
3. **원격진료는 신청/제안이 있을 때만** 큐에 오른다. Level만으로 자동 연결하지 않는다. 자가체크 결과에서 전 Level 신청 가능.  
4. 상태는 **요청 → 접수 → 진행 → 완료**. 알림톡은 RTMC가 보낸다. 의료진 제안 시 KOI가 발송을 요청한다.  
5. **확정하는 순간** 상담 접속 URL이 생기고 확정 알림톡에 들어간다. 화상은 KOI 별도 창, 종료 후 KOI가 대화를 AI 텍스트로 전환·저장하여 RTMC로 전달한다.
