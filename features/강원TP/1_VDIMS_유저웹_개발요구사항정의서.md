# VD-IMS · 유저웹 개발 요구사항 정의서

> 작성: ㈜리얼타임메디체크 자체 개발 항목
> 범위: VD-IMS(의료진용 웹) — 자가체크 내역·상세, 원격진료 운영 보드, 의료진 알림 / 유저웹(접종자용) — Level 안내·원격진료 신청·일정 응답
> 전제: Level 1~4는 연세대 분류모델이 **의료진 참고용으로 제안**한다. 원격진료는 Level과 무관하게 **의료진 제안** 또는 **접종자 신청**으로 시작한다. VD-IMS는 상태를 **요청 → 접수 → 진행 → 완료**로 운영한다. 알림톡은 RTMC가 발송하고, 예약 웹·화상·상담 대화 AI 텍스트 전환은 연계기관(KOI)이 제공·전달한다.

## 2. 핵심 운영 원칙

### 2-0. Level과 결정권한

- Level 1~4는 자가체크 결과를 분류한 **참고 정보**이다.
- Level 값으로 원격진료 버튼을 막거나, 자동 연계하지 않는다. 전 Level에서 원격진료를 열 수 있다.
- 목록 정렬은 Level 높은 건을 위에 두어 의료진이 우선 검토하기 쉽게 한다.

### 2-0-1. 원격진료 두 케이스

**케이스 1. 의료진 제안**  
자가체크 확인 → 의료진이 원격진료 요청 → **KOI가 알림톡 발송을 요청** → **RTMC가 알림톡 발송**(KOI 예약 웹 URL) → 접종자가 일정 선택(접수) → 확정(확인 팝업) → **확정 알림톡(일시 + 접속 URL)** → 진행 → 완료

**케이스 2. 접종자 신청**  
자가체크 결과에서 접종자가 원격진료 신청(전 Level) → 의료진 선택·해당 의료진 가용 일정 노출 → 접수 → 확정 → **확정 알림톡(일시 + 접속 URL)** → 진행 → 완료

공통: `요청 → 접수 → 확정 → 진행 → 완료`. 확정 전 변경·취소 가능. 확정 시점에 상담 접속 URL을 확정 알림톡에 넣는다. 완료 알림톡은 보내지 않는다. 당일 리마인드는 추가 검토.

## 3. 화면별 요구사항

### 3-1. 자가체크 내역

**표시**: 기존 컬럼 + `AI 판정(참고)` Level 배지, `원격진료` 상태  
**원격진료 상태**: `요청 / 접수 / 진행 / 완료` (예외: 취소, 불참)  
**정렬**: Level 높은 순 → 최신 자가체크  
**필터**: Level, 원격진료 상태, 회차  
Level 3·4 강조 방식과 회차별 행 여부는 와이어프레임에서 확정한다.

### 3-2. 자가체크 상세

**AI 분석**  
- Level + 판정 시각, “참고용 선별 · 진단 아님 · 실시 여부는 의료진 결정”  
- 증상 구조화, SHAP 기여도  
- 연락처는 의료진만. 연계기관 미전달

**원격진료 탭**  
- 케이스 1: 의료진 요청 → KOI 알림톡 요청 → RTMC 발송(예약 웹 URL). 접종자가 일정 선택  
- 케이스 2: 자가체크 결과에서 이미 신청된 건 표시, 접수·확정  
- 상태: 요청 · 접수 · 진행 · 완료 (취소·불참)  
- 확정 후 상담 접속 URL 표시, 확정 알림톡 미리보기  
- 화상은 KOI 별도 창. 전화는 VD-IMS 보유 번호로 의료진이 직접

### 3-3. 원격진료 운영 보드

운영 큐이며 AI 그래프는 복제하지 않는다. 상세로 들어가 분석·일정을 처리한다.

- 의료진 계정은 개인별로 발급한다. **원격진료 목록은 병원 공용**이다.
- **한 접종자(한 건)의 일정은 의사 한 명만 잡는다.** 가능 일정 알림톡을 보내는 계정이 담당이 된다. 다른 계정은 그 건을 선택할 수 없다.
- 목록만 보는 것으로는 잠그지 않는다. 알림톡 발송(일정 잡기) 시점에 담당이 고정된다.
- 의료진·기관 스케줄은 KOI가 관리한다. 같은 계정은 동시간 1건, 다른 계정은 동시간 가능.
- KPI: 요청, 접수, 진행, 완료  
- 확정 일정은 **오늘·내일·모레**를 진료 예정 시각 기준으로 보여 준다.  
- 부재 시에만 담당을 다른 계정으로 넘긴다.

### 3-4. 의료진 알림

- Level 판정 시 참고 알림(4는 강조). 자동 세션 생성 없음  
- 요청·접수·확정·불참 알림  
- 클릭 시 해당 상세 또는 원격진료 보드

### 3-5. 유저웹

- 전 Level에서 결과 안내 + 원격진료 신청 가능  
- 의료진 제안 수신 시: 알림톡의 KOI 예약 웹에서 일정 선택(확정 전 변경·취소 가능)  
- 본인 신청: 자가체크 결과에서 신청 후 의료진·일정 선택  
- 확정 후: 일시 + 접속 URL  
- 응급 안내(119) 고정

**알림톡 (RTMC 발송)**

| 종류 | 내용 |
|---|---|
| 예약 요청 | KOI 예약 웹 URL. 의료진 제안 시 KOI가 발송을 요청 |
| 예약 확정 | 확정 일시 + 상담 접속 URL |
| 상담 당일 | 리마인드(추가 검토, 긍정) |
| 상담 완료 | 발송하지 않음 |

## 4. 데이터 연동

| 연동 | 방향 | 비고 |
|---|---|---|
| 연세대 분류 결과 | 연세대 → VD-IMS | 유저 ID, 회차, Level, SHAP, 판정시각. 참고용 |
| 알림톡 발송 요청 | 연계기관 → RTMC | 예약요청·확정·당일리마인드. RTMC가 실제 발송 |
| 세션 URL | 연계기관 → VD-IMS | **확정 시점** 접속 URL. 확정 알림톡에 사용 |
| 상태 콜백 | 연계기관 → VD-IMS | 요청·접수·진행·완료·불참·취소. 상담 대화 AI 텍스트 전환본 포함 |

세션 생성 트리거는 “확정 알림톡 발송”이다. 상세의 “세션 열기”는 이미 발급된 URL로 입장한다.

---

## 5. 비기능

- 알림: 판정·신청·확정 전달 목표 1분 이내  
- 권한: 의료진만 상세·AI·연락처·원격진료 보드  
- 로그: Level 제안, 신청/제안, 알림톡, 확정, 세션 생성, 거절

---

## 6. 완료 기준

- [ ] 전 Level에서 원격진료 신청·의료진 제안이 가능하다
- [ ] Level은 참고로만 표시되고 자동 연계되지 않는다
- [ ] 케이스1: 의료진 요청 시 KOI 요청을 받아 RTMC가 예약 웹 URL 알림톡을 발송한다
- [ ] 케이스2: 자가체크 결과에서 전 Level 신청이 된다
- [ ] 상태가 요청 → 접수 → 진행 → 완료로 이어진다
- [ ] 확정 시 상담 접속 URL이 확정 알림톡에 포함된다
- [ ] 원격진료 보드에서 요청·접수·진행·완료를 구분한다
- [ ] 연계기관 콜백으로 상태와 AI 텍스트 전환된 상담 대화를 수신·저장한다. 진단·처방은 저장하지 않는다
